Jev란? TypeSafe의 판단 모델 해설

글을 쓰지 않고 고르기만 하는 모델입니다. System One 방식의 판단 모델이 무엇을 받아 무엇을 돌려주는지, 가격은 얼마인지, 독립 평가에서 어떤 위치인지, 어디서 한계가 드러나는지 정리합니다.

Jev는 글을 생성하지 않는 TypeSafe AI의 모델입니다. 텍스트나 JSON(상태, state라고 부릅니다)과 타입이 지정된 질문을 보내면, 질문마다 선택지, 점수, 또는 ‘예’일 확률을 돌려주고 그 답의 바탕이 된 확률도 함께 줍니다. TypeSafe는 2026년 9월 15일에 얼리 액세스로 공개했으며, 이를 최초의 ‘System One 모델’이라고 부릅니다. 다른 업체와 언론은 이런 종류의 모델을 판단 모델(decision model)이라고 부릅니다.

핵심 요약

  • Jev는 판단 모델이며 채팅이나 코딩 모델이 아닙니다. 텍스트를 읽고(이미지는 직접 켜야 하는 실험 기능입니다) 확률이 붙은 타입 지정 답을 돌려줍니다. 산문, 코드, 설명은 출력하지 않습니다.
  • 요청 하나에 상태 하나와 원하는 수만큼의 질문을 담습니다. Choice는 선택지 중 하나를 고르고, Score는 순서가 있는 단계로 평가하고, Noul은 ‘예’일 확률을 주고, Box(Jev 1.14 전용)는 이미지에서 대상의 위치를 찾습니다.
  • 가격은 입력 100만 토큰당 $0.042이고 출력은 무료입니다. 이 사이트 카탈로그의 유료 호스트도 같은 가격을 표시합니다.
  • Jev 1.13은 2026년 9월 15일에, Jev 1.14는 2026년 10월 14일에 나왔습니다. 가중치는 비공개이며 호스팅 API로만 쓸 수 있습니다.
  • Artificial Analysis는 Decision Index에서 Jev 1.13에 58점을 주었습니다. 출시 시점에 판단 모델 중 1위였고 Claude Haiku 5.5(Low)보다 3점 낮았으며, 100만 작업당 비용은 $42 대 $184입니다. 이후 더 높은 점수를 받은 판단 모델이 나왔습니다.

Jev란 무엇인가

TypeSafe AI는 샌프란시스코의 회사로, 2024년에 Diogo Almeida가 Erik Gafni, Sasha Sheng과 함께 세웠습니다. Almeida는 OpenAI에서 인간 피드백 기반 강화학습(RLHF)을 연구했습니다. TechCrunch에 따르면 이 회사는 공개 몇 주 뒤인 10월 9일에 8억 7천만 달러를 투자받았고 기업 가치는 75억 달러였습니다.

TypeSafe의 주장은 채팅 모델이 사람이 읽기 좋아하는 답을 내도록 조정되어 있어서, 소프트웨어가 출력을 받아 쓰는 용도에는 맞지 않는다는 것입니다. Jev는 이 회사가 ‘보정된 판단을 위한 강화학습’(RLCD)이라고 부르는 방법으로 학습합니다. 많은 예측에서 확률 0.8로 낸 답이 약 80% 맞는 것이 목표입니다. 아키텍처, 가중치, 논문은 공개되지 않았습니다. TechCrunch는 이 모델을 트랜스포머 기반이라고 설명하고, Almeida는 학습 데이터가 전부 합성 데이터라고 말했습니다.

두 이름에는 각각 유래가 있습니다. ‘System One’은 대니얼 카너먼의 『생각에 관한 생각』에 나오는 빠르고 직관적인 사고에서 왔습니다. ‘Jev’는 경제학자 윌리엄 스탠리 제번스에서 따왔으며, 자원을 더 효율적으로 쓰면 총소비량이 늘어나는 경향이 있다는 제번스의 역설을 가리킵니다.

요청이 처리되는 방식

모든 요청은 POST https://api.typesafe.ai/v1/systemone 엔드포인트 하나로 보내며, model 필드가 버전을 정합니다. 본문에는 state(문자열, JSON 객체, 또는 텍스트 배열)와 questions 맵이 들어갑니다. 질문마다 ID, type, instructions가 있고, Choice와 Score는 선택지나 단계를 정의하는 criteria도 있어야 합니다. ID는 사용자의 코드를 위한 것이며, TypeSafe 문서에 따르면 모델에는 전달되지 않습니다. 따라서 질문 전체를 instructions에 적어야 합니다.

질문용도답변 필드
Choice목록에서 선택지 하나를 고름. TypeSafe 공개 글에 따르면 최대 255개choice, probabilities, confidence
Score직접 설명한 순서형 단계로 평가score(단계 사이의 값도 가능), legend, probabilities, confidence
Noul어떤 진술이 참인지 판단noul, 0에서 1 사이의 확률
Box(Jev 1.14)이미지에서 대상 하나의 위치를 찾음box(네 변, 이미지 크기에 대한 비율), confidence

한 요청 안의 질문은 모두 같은 상태에 대해 병렬로, 서로 독립적으로 평가되므로 답이 서로 영향을 주지 않습니다. 뒤의 질문이 앞의 답에 의존한다면 두 번째 요청이 필요합니다. TypeSafe는 질문 하나에 좁은 판단 하나만 묻고, 답은 직접 만든 코드에서 조합하라고 권합니다. 예를 들어 ‘이 피치를 평가해 줘’ 대신 시장 규모, 기술적 실현 가능성, 차별화를 따로 묻고 점수에 직접 가중치를 줍니다.

confidence는 확률이 얼마나 한쪽에 몰려 있는지를 0에서 1로 요약한 값입니다. 고르게 나뉘면 0, 하나의 선택지에 확률이 모두 몰리면 1입니다. 선택지가 n개인 Choice에서는 (최고 확률 - 1/n) / (1 - 1/n)입니다. Noul에 confidence 필드가 없는 것은 0.5에 가까운 값이 곧 모델이 확신하지 못한다는 뜻이기 때문입니다. TypeSafe는 세 구간으로 나눠 다루라고 제안합니다. 확신도가 높으면 자동으로 실행하고, 중간이면 확인을 요청하고, 낮으면 사람에게 넘깁니다. 임계값은 잘못 판단했을 때의 비용에 맞춰 정합니다.

보정은 예측 묶음 전체에 대한 성질입니다. TypeSafe 문서는 개별 답이 맞는다고 보장하지 않는다고 밝힙니다. 공개 글의 ‘환각이 없다’는 주장은 답이 사용자가 준 선택지 중 하나라는 뜻이지, 답이 맞다는 뜻이 아닙니다.

어디에 쓰나

TypeSafe의 cookbook은 티켓과 의도 라우팅, 함수 호출, LLM 입출력 가드레일, 인용 확인, 검색된 문단 채점, 재순위화, 계층형 문서 분류를 다룹니다. 언론에 인용된 초기 사용자들은 기존 파이프라인 안에서 모델을 바꿔 끼운 사례를 이야기합니다. TechCrunch는 Vercel의 한 엔지니어가 명령어 안전성 분류기에서 OpenAI 모델을 Jev로 바꿔 5배에서 18배 빠르고 더 정확한 결과를 얻었다고 보도했습니다. 같은 기사는 Bryo AI의 CTO도 인용했는데, 이메일 분류에서는 Gemini가 Jev보다 약간 더 정확했지만 10배에서 20배 비쌌다고 합니다.

Jev는 채팅 어시스턴트나 코딩 에이전트 뒤의 언어 모델을 대체하지 않습니다. TypeSafe 문서가 이를 직접 밝히며 Claude Code, Cursor, Copilot, Muse Spark, Grok Bot 등을 Jev로 구동할 수 없는 도구로 꼽습니다. 문서가 제시하는 방식은 에이전트가 Jev를 호출하는 코드를 쓰게 하고, 제품 안의 판단은 Jev가 맡는 것입니다.

별칭 두 개가 각각 버전을 가리킵니다. 이 글을 확인한 10월 23일 기준으로 TypeSafe의 Models 페이지는 jev-latest를 jev-1.13.0, jev-preview를 jev-1.14.0으로 표시했습니다. 1.14 릴리스 글을 전한 보도에 따르면 jev-latest는 10월 14일에서 약 일주일 뒤 1.14.0으로 옮겨질 예정이었습니다. 별칭이 옮겨 가면 코드를 바꾸지 않아도 답이 달라질 수 있어서, TypeSafe는 특정 버전에 맞춰 임계값을 조정했다면 버전이 붙은 ID를 보내라고 권합니다. 응답의 model 필드에는 실제로 답한 버전이 기록됩니다. MarkTechPost가 릴리스 글을 요약한 바에 따르면 TypeSafe는 1.13 종료 60일 전, 1.14 종료 30일 전에 알립니다. 이 사이트는 별칭과 1.13 경로를 Jev 한 페이지에, 1.14를 별도 페이지에 정리합니다.

두 버전 모두 TypeSafe-Danger-Zone-Images: true 헤더를 보내면 이미지를 받습니다. TypeSafe는 이미지와 Box를 ‘dreamer-ready’로 표시하는데, 프로토타입용이라는 뜻입니다. 요청 형식, 답변, 제한이 릴리스 사이에 바뀔 수 있고 정확도도 텍스트보다 낮습니다. 이미지는 PNG 또는 JPEG여야 하며 파일당 16 MiB 이하, 한 변이 280에서 1,568픽셀이어야 하고 입력 토큰으로 과금됩니다. Box 질문은 대상이 없어도 매번 네 변을 돌려줍니다. 그래서 TypeSafe는 대상이 보이는지 묻는 Noul을 함께 쓰라고 권합니다. 오디오와 비디오는 받지 않습니다.

영어가 주 학습 언어입니다. TypeSafe는 중국어·일본어·한국어 문자를 포함한 다른 언어도 처리하지만 성능이 고르지는 않다고 밝혔습니다. 1.14에서는 다국어 입력의 향상 폭이 가장 클 것으로 예상했으나 점수는 공개하지 않았습니다.

Jev 가격

100만 토큰당 미국 달러 기준이며, 2026년 10월 23일에 TypeSafe의 Models 페이지와 이 사이트의 카탈로그에서 확인했습니다.

TypeSafe 자체 API는 이 사이트가 읽는 models.dev 데이터에 없으므로 모델 페이지에는 공식 가격이 표시되지 않습니다. 카탈로그의 모든 호스트가 입력 $0.042, 출력 무료로 표시하며, free로 표기된 경로 하나만 $0입니다. 카탈로그의 Jev 컨텍스트 수치는 호스트에 따라 32K에서 262K까지이며, TypeSafe가 공개한 세 가지 한도인 질문당 32K, 요청당 64K, 롱컨텍스트 헤더 사용 시 262K와 가깝습니다.

Jev의 성능

TypeSafe의 공개 글은 자체 워크플로 평가에서 Jev가 프런티어 LLM보다 193.6배 빠르고 444.6배 저렴하다고 주장하며, 엔드투엔드 응답 시간은 70에서 500밀리초라고 합니다. 같은 글은 이 이득이 실제 사용에서는 상한에 가까운 수준이고, 워크플로는 자사 모델 역량 팀이 만들었으며, 참조 답안은 대형 LLM 두 개의 평균이라고도 밝힙니다. 1.14에 대해서는 점수표 없이 차트만 공개했고, 비교 대상은 오픈 웨이트 모델뿐이며, 이 비교가 자사 모델에 유리했을 가능성이 높다고 했습니다.

Artificial Analysis는 10월 13일에 Decision Index v1.0을 공개했습니다. AA-Omniscience-Decision(지식과 환각), HLE-MultiChoice(추론), When2Call(도구 호출), WildGuardTest(안전 분류) 네 가지 테스트를 같은 비중으로 평균합니다. Jev 1.13의 결과는 다음과 같습니다.

작업 100만 건당 비용$42

언어 모델과 비교하면 Claude Haiku 5.5(Low)는 61점에 작업당 1.4초, 100만 작업당 $184였고, GPT-6 Luna(Low)는 55점에 1.5초, $131이었습니다. 지식 문제에서는 LLM이 앞섰습니다. AA-Omniscience-Decision 정확도는 52와 66이었고 판단 모델은 28에서 41이었습니다. Artificial Analysis는 판단 모델이 과신하는 경향도 확인했습니다. 거의 모든 확률 구간에서 실제 정확도가 제시된 확률보다 낮았고, 주로 지식과 추론 문제에서 그랬으며, 도구 호출과 분류에서는 보정이 비교적 잘 맞았습니다.

Arize는 Jev를 내장 평가 모델로 제공하는 평가 플랫폼으로, 출시 약 3주 뒤에 Jev 1.13을 다른 판단 모델 7개와 비교했습니다. Jev는 RAGTruth 환각 탐지에서 Balanced Accuracy 85.5%, Phoenix 평가기 13종에서 91.1%, 에이전트 라우팅 52건 중 49건 정답이었습니다. 보정 오차 0.023은 8개 모델 중 가장 낮았지만 Liquid d1과는 구간이 겹쳤습니다. 상위 모델들의 정확도 차이는 서로의 신뢰구간 안에 있었습니다. 표현 테스트에서는 환각 질문을 반대로 표현해도 Jev의 ROC AUC가 0.93으로 유지된 반면, 다른 여러 모델은 0.5 아래로 떨어졌습니다. Arize는 어떤 모델이든 같은 질문을 두 가지 표현으로 모두 시험한 뒤에 점수를 믿으라고 권합니다.

순위는 빠르게 바뀝니다. 10월 22일 TechCrunch는 최신 Jev를 Artificial Analysis Decision Index에서 3위, AIM System One Index에서 7위로 소개했으며, Liquid d1-ultra 같은 더 새로운 모델 다음 순위입니다. 또 TypeSafe의 모델이 한 모델 게이트웨이에서 가장 많이 호출되는 판단 모델이라고 보도했습니다.

한계와 데이터 처리

TypeSafe는 10월 2일에 마지막으로 점검한 페이지에서 1.13의 약점을 다음과 같이 꼽습니다.

  • Jev는 질문을 글자 그대로 읽습니다. 정확한 조건과 경계 사례를 criteria에 적으세요.
  • 개수를 안정적으로 세지 못하고 산술과 날짜 비교에 약합니다. Jev로 구성 요소를 추출하고 계산은 코드에서 하세요.
  • 이중 부정과 여러 단계의 추론은 정확도를 떨어뜨립니다.
  • 상태에 관련 없는 세부 내용이 늘어날수록 정확도가 떨어지므로 보내기 전에 걸러 내세요.
  • 상태 안의 텍스트가 답을 유도할 수 있습니다. TypeSafe에 따르면 Jev는 상태를 기본적으로 적대적인 입력으로 취급하지 않습니다.
  • Choice 선택지의 순서가 답을 첫 번째 선택지 쪽으로 기울일 수 있습니다. 순서를 바꿔 확인하세요.
  • 글을 생성하도록 학습되지 않았습니다.

속도 제한은 조직별로 설정되며, 한도를 넘은 요청에는 429가 반환됩니다. TypeSafe는 Jev가 고객의 요청이나 응답으로 학습되지 않으며, 기업 고객은 데이터를 보관하지 않는 제로 데이터 보존(ZDR)을 협의할 수 있다고 밝힙니다. 모든 계정이 같은 가중치를 쓰며 Jev는 고객 데이터로 파인튜닝되지 않으므로, 도메인 지식은 상태와 criteria에 넣어야 합니다.

자주 묻는 질문

Jev란 무엇인가요?

TypeSafe AI의 판단 모델입니다. 텍스트나 JSON과 타입이 지정된 질문을 보내면, 생성된 글 대신 선택지, 점수, 또는 ‘예’일 확률을 확신도와 함께 돌려줍니다. 2026년 9월 15일에 얼리 액세스로 공개되었습니다.

Jev는 LLM인가요?

아니요. TypeSafe는 LLM처럼 자연어를 읽지만 출력은 타입이 지정된 답과 확률뿐인 트랜스포머 기반 모델이라고 설명합니다. 산문이나 코드를 쓰지 않고, 대화하지 않고, 도구를 호출하지 않습니다.

Jev는 얼마인가요?

입력 100만 토큰당 $0.042(10억 토큰당 $42)이고 출력 토큰은 무료입니다. 이미지는 같은 가격의 입력 토큰으로 과금됩니다. 가격은 2026년 10월 23일에 확인한 것이며, 현재 가격은 모델 페이지에 있습니다.

Jev 1.13과 Jev 1.14는 무엇이 다른가요?

Jev 1.14는 이미지에서 객체의 위치를 찾는 Box 질문 유형을 추가했고, TypeSafe는 다국어 정확도가 더 높아질 것으로 예상합니다. 두 버전 모두 옵트인 헤더로 이미지와 262K 롱컨텍스트 모드를 받으며 가격도 같습니다.

판단 모델이란 무엇인가요?

글을 생성하는 대신 사용자가 정의한 선택지 중에서 고르고 각각의 확률을 알려 주는 모델입니다. TypeSafe는 이를 System One 모델이라고 부릅니다. 이제 다른 제작사도 자체 모델을 내놓고 있으며, 이 사이트의 카탈로그에는 종류가 decision인 항목이 31개 있습니다.

Jev를 직접 실행할 수 있나요?

아니요. 가중치와 아키텍처가 공개되지 않았고 Jev는 호스팅 API로만 쓸 수 있습니다. Cloudflare의 Clef처럼 오픈 웨이트로 나온 판단 모델도 있습니다.

Jev도 환각을 일으키나요?

답이 사용자가 준 선택지 안으로 제한되므로, 형식이 잘못된 값이나 제공하지 않은 선택지를 돌려줄 수는 없습니다. 그래도 틀린 선택지를 고를 수는 있으며, Artificial Analysis는 판단 모델이 지식과 추론 문제에서 과신한다는 점을 확인했습니다.
