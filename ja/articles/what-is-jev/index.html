Jev とは？TypeSafe の判断モデルを解説

文章を書かず、選ぶモデルです。System One 型の判断モデルが何を受け取り何を返すのか、料金、独立した評価での位置づけ、苦手な点をまとめます。

Jev は TypeSafe AI のモデルで、文章を生成しません。テキストまたは JSON（状態、state と呼びます）と、型付きの質問を送ると、質問ごとに選択肢、スコア、または「はい」の確率が返ります。その答えの根拠となる確率も一緒に返されます。TypeSafe は 2026年9月15日 にアーリーアクセスとして公開し、これを最初の「System One モデル」と呼んでいます。ほかのベンダーや報道では、この種類のモデルを判断モデル（decision model）と呼びます。

要点

  • Jev は判断モデルで、チャットやコーディング用のモデルではありません。テキストを読み（画像は有効化が必要な実験機能）、確率つきの型付きの答えを返します。文章、コード、説明は出力しません。
  • 1 回のリクエストには 1 つの状態と任意の数の質問を載せられます。Choice は選択肢から 1 つを選び、Score は順序のあるレベルで評価し、Noul は「はい」の確率を返し、Box（Jev 1.14 のみ）は画像内の対象の位置を示します。
  • 料金は 100 万入力トークンあたり $0.042 で、出力は無料です。当サイトのカタログにある有料ホストも同じ料金です。
  • Jev 1.13 は 2026年9月15日、Jev 1.14 は 2026年10月14日 に公開されました。重みは非公開で、ホスト型 API でしか使えません。
  • Artificial Analysis は Decision Index で Jev 1.13 に 58 点をつけました。公開時点で判断モデルの首位で、Claude Haiku 5.5（Low）より 3 点低く、100 万タスクあたりのコストは $42 対 $184 です。その後、より高いスコアの判断モデルが登場しています。

Jev とは

TypeSafe AI はサンフランシスコの企業で、2024 年に Diogo Almeida が Erik Gafni、Sasha Sheng とともに設立しました。Almeida は OpenAI で人間のフィードバックによる強化学習（RLHF）に携わっていました。TechCrunch によると、同社は公開から数週間後の 10 月 9 日に 8 億 7,000 万ドルを調達し、評価額は 75 億ドルでした。

TypeSafe の主張は、チャットモデルは人が読みたがる答えを出すように調整されており、ソフトウェアが出力を受け取る用途には合わない、というものです。Jev は、同社が「校正された判断のための強化学習」（RLCD）と呼ぶ手法で訓練されています。多数の予測のうち、確率 0.8 とされた答えが約 80% 当たることが目標です。アーキテクチャ、重み、論文は公開されていません。TechCrunch はこのモデルを Transformer ベースと説明しており、Almeida は訓練データがすべて合成データだと同媒体に語っています。

名前にはそれぞれ由来があります。「System One」は、ダニエル・カーネマンの『ファスト＆スロー』にある、速く直感的な思考から来ています。「Jev」は経済学者ウィリアム・スタンレー・ジェヴォンズにちなみ、資源をより効率的に使うと総消費量が増える傾向がある、というジェヴォンズのパラドックスを踏まえています。

リクエストの仕組み

すべてのリクエストは 1 つのエンドポイント POST https://api.typesafe.ai/v1/systemone に送り、model フィールドでバージョンを選びます。本文には state（文字列、JSON オブジェクト、またはテキストの配列）と questions のマップを入れます。各質問には ID、type、instructions があり、Choice と Score ではさらに選択肢やレベルを定める criteria が必要です。ID はあなたのコードで使うためのもので、TypeSafe のドキュメントによればモデルには送られません。そのため、質問の全文を instructions に書く必要があります。

質問用途回答フィールド
Choice一覧から選択肢を 1 つ選ぶ。TypeSafe の公開記事によれば最大 255 件choice、probabilities、confidence
Score自分で記述した順序つきレベルで評価するscore（レベルの間の値も可）、legend、probabilities、confidence
Noul記述が正しいかどうかを判定するnoul、0 から 1 の確率
Box（Jev 1.14）画像内の対象を 1 つ見つけるbox（四辺、画像サイズに対する割合）、confidence

1 回のリクエスト内の質問は、すべて同じ状態に対して並列かつ独立に評価されるため、答え同士は影響しません。後の質問が前の答えに依存する場合は、2 回目のリクエストが必要です。TypeSafe は、質問ごとに絞った判断を 1 つだけ尋ね、答えは自分のコードで組み合わせるよう勧めています。たとえば「このピッチを評価して」と尋ねる代わりに、市場規模、技術的な実現可能性、差別化を別々に尋ね、スコアを自分で重みづけします。

confidence は確率の集中度を 0 から 1 でまとめたもので、均等に分かれていれば 0、1 つの選択肢にすべての確率が集まっていれば 1 です。n 個の選択肢がある Choice では (最大確率 - 1/n) / (1 - 1/n) です。Noul に confidence フィールドがないのは、0.5 に近い値がそのままモデルの迷いを表すからです。TypeSafe は 3 段階の扱いを提案しています。確信度が高ければ自動で実行し、中間なら確認を求め、低ければ人に回します。しきい値は、誤判断のコストに応じて決めます。

校正とは、予測の集まり全体についての性質です。TypeSafe のドキュメントは、個々の答えが正しいことを保証するものではないと述べています。公開記事の「ハルシネーションを起こさない」という主張は、答えがあなたの与えた選択肢のどれかになるという意味で、答えが正しいという意味ではありません。

主な用途

TypeSafe の cookbook は、チケットや意図のルーティング、関数呼び出し、LLM の入出力のガードレール、引用の確認、検索結果の採点、リランキング、階層的な文書分類を扱っています。報道に登場する初期の利用者が語るのは、既存のパイプライン内でのモデルの置き換えです。TechCrunch は、Vercel のエンジニアがコマンドの安全性を判定する分類器で OpenAI のモデルを Jev に替え、5 倍から 18 倍速く、精度も上がったと報じました。同記事は Bryo AI の CTO の話も引いており、メール分類では Gemini の方が Jev よりわずかに正確だが、10 倍から 20 倍高いとのことです。

Jev は、チャットアシスタントやコーディングエージェントの背後にある言語モデルの代わりにはなりません。TypeSafe のドキュメントははっきりそう述べており、Claude Code、Cursor、Copilot、Muse Spark、Grok Bot などを、Jev では動かせないツールとして挙げています。文書で示されている使い方は、エージェントに Jev を呼び出すコードを書かせ、製品内の判断を Jev に任せる形です。

2 つのエイリアスがバージョンを指しています。このページを確認した 10 月 23 日の時点で、TypeSafe の Models ページは jev-latest を jev-1.13.0、jev-preview を jev-1.14.0 としていました。1.14 のリリース記事を伝える報道によると、jev-latest は 10 月 14 日の約 1 週間後に 1.14.0 へ移る予定でした。エイリアスが動くと、コードを変えなくても答えが変わることがあります。そのため TypeSafe は、あるバージョンに合わせてしきい値を調整したなら、バージョン付きの ID を指定するよう勧めています。レスポンスの model フィールドには、実際に答えたバージョンが記録されます。MarkTechPost によるリリース記事の要約では、TypeSafe は 1.13 の廃止の 60 日前、1.14 の廃止の 30 日前に通知するとされています。当サイトでは、エイリアスと 1.13 の経路を Jev の 1 ページに、1.14 を専用のページにまとめています。

どちらのバージョンも、TypeSafe-Danger-Zone-Images: true ヘッダーをつければ画像を受け付けます。TypeSafe は画像と Box を「dreamer-ready」としており、これはプロトタイプ向けという意味です。リクエスト形式、答え、制限はリリース間で変わる可能性があり、精度もテキストより低くなります。画像は PNG または JPEG で、1 ファイル 16 MiB まで、各辺 280 から 1,568 ピクセルで、入力トークンとして課金されます。Box の質問は、対象がなくても毎回四辺を返します。そのため TypeSafe は、対象が見えるかどうかを尋ねる Noul を組み合わせるよう勧めています。音声と動画は受け付けません。

英語が主な訓練言語です。TypeSafe によると、中国語・日本語・韓国語の文字を含む他言語も扱えますが、精度は均一ではありません。1.14 では多言語入力の改善が最も大きいと見込んでいましたが、スコアは公開していません。

Jev の性能

TypeSafe の公開記事は、自社のワークフロー評価で、フロンティア LLM より 193.6 倍速く、444.6 倍安いと主張し、エンドツーエンドの応答時間は 70 から 500 ミリ秒としています。同じ記事には、この改善幅は実際の利用では上限に近いこと、ワークフローは同社のモデル能力チームが作成したこと、参照用の答えは 2 つの大型 LLM の平均であることも書かれています。1.14 については、スコア表のないグラフだけを公開し、比較対象はオープンウェイトのモデルに限られ、比較は自社モデルに有利になっている可能性が高いとしています。

Artificial Analysis は 10 月 13 日に Decision Index v1.0 を公開しました。AA-Omniscience-Decision（知識とハルシネーション）、HLE-MultiChoice（推論）、When2Call（ツール呼び出し）、WildGuardTest（安全性の分類）の 4 つのテストを同じ重みで平均したものです。Jev 1.13 の結果は次のとおりです。

言語モデルと比べると、Claude Haiku 5.5（Low）は 61 点で、1 タスク 1.4 秒、100 万タスクあたり $184 でした。GPT-6 Luna（Low）は 55 点で、1.5 秒、$131 です。知識では LLM が上回り、AA-Omniscience-Decision の正答率は 52 と 66 で、判断モデルは 28 から 41 でした。Artificial Analysis は、判断モデルが過信しがちなことも確認しています。ほぼすべての確率帯で、実際の正答率が示された確率を下回りました。主な原因は知識と推論の問題で、ツール呼び出しと分類では校正が比較的よく取れていました。

Arize は Jev を組み込みの評価モデルとして提供する評価プラットフォームで、公開の約 3 週間後に Jev 1.13 を他の 7 つの判断モデルと比較しました。Jev は、RAGTruth のハルシネーション検出で Balanced Accuracy 85.5%、13 の Phoenix 評価スイートで 91.1%、エージェントのルーティング 52 件のうち 49 件で正解でした。校正誤差 0.023 は 8 モデルで最も低いものの、Liquid d1 とは区間が重なっています。上位モデルの精度の差は、互いの信頼区間に収まっていました。表現のテストでは、ハルシネーションの質問を逆の言い方にしても Jev の ROC AUC は 0.93 のままでしたが、ほかの複数のモデルは 0.5 を下回りました。Arize は、どのモデルでも同じ質問を 2 通りの言い方で試してから、スコアを信用するよう勧めています。

順位は短期間で変わります。10 月 22 日の TechCrunch は、最新の Jev を Artificial Analysis の Decision Index で 3 位、AIM System One Index で 7 位とし、Liquid d1-ultra などの新しいモデルに次ぐ位置だと伝えました。また、TypeSafe のモデルはあるモデルゲートウェイで最も多く呼び出されている判断モデルだと報じています。

制限とデータの扱い

TypeSafe は、10 月 2 日に最後に見直したページで、1.13 の弱点を次のように挙げています。

  • Jev は質問を文字どおりに読みます。正確な条件と境界のケースを criteria に書いてください。
  • 数え上げは確実ではなく、算術や日付の比較も苦手です。Jev で要素を抽出し、計算はコードで行います。
  • 二重否定や複数段階の推論では精度が落ちます。
  • 無関係な情報が状態に増えるほど精度が下がるため、送る前にフィルターします。
  • 状態の中のテキストが答えを誘導することがあります。TypeSafe によると、Jev は状態を最初から敵対的なものとして扱いません。
  • Choice の選択肢の順序によって、答えが最初の選択肢に寄ることがあります。順序を入れ替えて確認してください。
  • 文章を生成するようには訓練されていません。

レート制限は組織ごとに設定され、上限を超えたリクエストには 429 が返ります。TypeSafe は、Jev が顧客のリクエストやレスポンスで訓練されることはなく、企業顧客はゼロデータリテンション（データを保持しない取り決め）を結べると述べています。すべてのアカウントが同じ重みを使い、Jev は顧客データでファインチューニングされないため、ドメイン知識は状態と criteria に入れます。

よくある質問

Jev とは何ですか？

TypeSafe AI の判断モデルです。テキストまたは JSON と型付きの質問を送ると、生成した文章ではなく、選択肢、スコア、または「はい」の確率を、確信度とともに返します。2026年9月15日 にアーリーアクセスとして公開されました。

Jev は LLM ですか？

いいえ。TypeSafe は、LLM と同じように自然言語を読むものの、出力は型付きの答えと確率だけの Transformer ベースのモデルだと説明しています。文章やコードを書かず、会話もせず、ツールも呼び出しません。

Jev の料金はいくらですか？

入力トークン 100 万あたり $0.042（10 億あたり $42）で、出力トークンは無料です。画像は入力トークンとして同じ料金で課金されます。価格は 2026年10月23日に確認したもので、最新の価格は各モデルのページにあります。

Jev 1.13 と Jev 1.14 の違いは何ですか？

Jev 1.14 は、画像内の物体の位置を示す Box の質問タイプを追加し、TypeSafe は多言語での精度向上を見込んでいます。どちらもオプトインのヘッダーで画像と 262K の長コンテキストモードを受け付け、料金は同じです。

判断モデルとは何ですか？

文章を生成する代わりに、あなたが定義した選択肢から選び、それぞれの確率を返すモデルです。TypeSafe は System One モデルと呼んでいます。ほかのメーカーも自社版を出すようになり、当サイトのカタログには種別が decision のエントリーが 31 件あります。

Jev を自分で動かせますか？

いいえ。重みとアーキテクチャは非公開で、Jev はホスト型 API でしか使えません。Cloudflare の Clef のように、重みを公開している判断モデルもあります。

Jev はハルシネーションを起こしますか？

答えはあなたが与えた選択肢の範囲に限られるため、形式の崩れた値や、用意していない選択肢を返すことはありません。ただし、誤った選択肢を選ぶことはあり、Artificial Analysis は判断モデルが知識や推論の問題で過信しがちだと確認しています。
