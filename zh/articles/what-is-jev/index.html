Jev 是什么？TypeSafe 决策模型详解

一个只做选择、不写文字的模型。System One 决策模型接收什么、返回什么，价格多少，独立测试怎么评价它，以及它在哪些地方会出错。

Jev 是 TypeSafe AI 的模型，它不生成文字。你给它一段文本或 JSON（称为状态，state），再附上若干类型化的问题；对每个问题，它返回一个选项、一个分数或一个是/否概率，同时给出答案背后的概率分布。TypeSafe 于 2026年9月15日 以早期访问的形式发布了它，并称其为第一个「System One 模型」。其他厂商和媒体把这一类模型叫作决策模型（decision model）。

简短结论

  • Jev 是决策模型，不是聊天或编程模型。它读取文本（图像是需要主动开启的实验功能），返回带概率的类型化答案，不产出散文、代码或解释。
  • 一次请求带一个状态和任意多个问题。Choice 从选项里挑一个，Score 按有序等级打分，Noul 给出「是」的概率，Box（仅 Jev 1.14）在图像里定位某个东西。
  • 输入每百万 token $0.042，输出免费。本站 catalog 里的付费宿主报的都是同一个价。
  • Jev 1.13 于 2026年9月15日 发布，Jev 1.14 于 2026年10月14日 发布。权重不公开，只能通过托管 API 使用。
  • Artificial Analysis 在其 Decision Index 上给 Jev 1.13 打了 58 分，在发布时是决策模型里的第一，比 Claude Haiku 5.5（Low）低 3 分，每百万任务成本 $42，对方为 $184。之后出现的新决策模型得分更高。

Jev 是什么

TypeSafe AI 是一家位于旧金山的公司，2024 年由 Diogo Almeida 与 Erik Gafni、Sasha Sheng 创立。Almeida 曾在 OpenAI 参与基于人类反馈的强化学习（RLHF）。TechCrunch 报道，该公司在发布几周后的 10 月 9 日完成 8.7 亿美元融资，估值 75 亿美元。

TypeSafe 的论点是：聊天模型被调教成输出人愿意读的答案，而软件消费输出时并不适配这一点。Jev 用该公司称为「面向校准决策的强化学习」（RLCD）的方法训练，目标是在大量预测中，给出 0.8 概率的答案大约有 80% 是对的。TypeSafe 没有公布架构、权重和论文。TechCrunch 称它是基于 Transformer 的模型，Almeida 告诉该媒体，训练数据全部是合成数据。

两个名字各有出处。「System One」取自 Daniel Kahneman《思考，快与慢》里快速、直觉式的思维。「Jev」取自经济学家 William Stanley Jevons，他的悖论说的是：资源使用得更高效，总消耗反而往往上升。

请求是怎么工作的

所有请求发往同一个端点 POST https://api.typesafe.ai/v1/systemone，由 model 字段选择版本。请求体包含 state（字符串、JSON 对象或文本数组）和 questions 映射。每个问题有 ID、type、instructions，Choice 和 Score 还要有 criteria 来定义选项或等级。ID 只给你的代码用，TypeSafe 文档说明它不会发给模型，所以完整的问题必须写在 instructions 里。

问题类型用途答案字段
Choice从列表里挑一个选项；TypeSafe 发布文章称最多 255 个选项choice、probabilities、confidence
Score按你描述的有序等级打分score（可落在两个等级之间）、legend、probabilities、confidence
Noul判断一个陈述是否成立noul，0 到 1 的概率
Box（Jev 1.14）在图像里定位一个目标box（四条边，为图像宽高的比例）、confidence

同一请求里的所有问题针对同一个状态并行、独立地求值，答案之间互不影响。如果后一个问题依赖前一个答案，就要发第二次请求。TypeSafe 建议每个问题只问一个窄判断，再在自己的代码里组合答案。例如不要问「给这个项目打分」，而是分别问市场规模、技术可行性和差异化，再自己加权。

confidence 概括概率的集中程度：均匀分布为 0，概率全压在一个选项上为 1。对有 n 个选项的 Choice，公式是 (最高概率 - 1/n) / (1 - 1/n)。Noul 没有 confidence 字段，因为接近 0.5 的值本身就表示模型拿不准。TypeSafe 建议分三档处理：高置信度时自动执行，中间档请用户确认，低置信度时转人工，阈值按判断出错的代价调整。

校准描述的是一批预测的整体表现。TypeSafe 文档说明，它不保证任何单个答案正确；发布文章里「不会幻觉」的说法，指的是答案一定落在你给出的选项里，而不是答案一定正确。

用来做什么

TypeSafe 的 cookbook 涵盖工单与意图路由、函数调用、LLM 输入输出的护栏、引用核对、给检索到的段落打分、重排序和层级式文档分类。媒体引用的早期用户讲的是在现有流程里替换模型。TechCrunch 报道，Vercel 的一位工程师把命令安全分类器里的 OpenAI 模型换成 Jev，速度快 5 到 18 倍，准确率也更高。同一篇报道还引用了 Bryo AI 的 CTO：他测试邮件分类时发现 Gemini 比 Jev 略准，但贵 10 到 20 倍。

Jev 不能替代聊天助手或编程 agent 背后的语言模型。TypeSafe 文档直接说明了这一点，并点名 Claude Code、Cursor、Copilot、Muse Spark 和 Grok Bot 等工具无法由它驱动。文档里的用法是：用 agent 去写调用 Jev 的代码，让 Jev 负责产品内部的各项判断。

有两个别名指向具体版本。本文核对于 10 月 23 日，当时 TypeSafe 的 Models 页面把 jev-latest 列为 jev-1.13.0，jev-preview 列为 jev-1.14.0。媒体对 1.14 发布文章的转述称，jev-latest 计划在 10 月 14 日之后约一周移到 1.14.0。别名移动后，你的代码没有改动，答案却可能变化，所以 TypeSafe 建议：如果按某个版本调过阈值，就直接写带版本号的 ID。响应里的 model 字段会记录是哪个版本给出的答案。据 MarkTechPost 对发布文章的转述，TypeSafe 在下线 1.13 前给 60 天通知，下线 1.14 前给 30 天通知。本站把别名和 1.13 的渠道放在 Jev 一页，1.14 放在单独的页面。

两个版本都接受图像，需要带上 TypeSafe-Danger-Zone-Images: true 请求头。TypeSafe 把图像和 Box 标为「dreamer-ready」，意思是只适合做原型：请求格式、答案和限制都可能在版本之间变化，准确率也低于纯文本。图像须为 PNG 或 JPEG，单文件最大 16 MiB，每边 280 到 1,568 像素，按输入 token 计费。Box 问题每次都会返回四条边，即使目标不在图里，所以 TypeSafe 建议配一个 Noul，先问目标是否可见。音频和视频不支持。

英语是主要训练语言。TypeSafe 表示其他语言（包括中日韩文字）可以处理，但效果不均衡，并预期 1.14 在多语言输入上提升最大，但没有公布分数。

Jev 表现如何

TypeSafe 发布文章称，在它自己的工作流评测里，Jev 比前沿 LLM 快 193.6 倍、便宜 444.6 倍，端到端耗时 70 到 500 毫秒。同一篇文章也说明，这些收益处于真实场景的高端，工作流由其模型能力团队编写，参考答案是两个大型 LLM 的平均值。对于 1.14，TypeSafe 只发布了没有分数表的图表，只和开放权重模型比较，并表示这样的比较可能偏向自家模型。

Artificial Analysis 于 10 月 13 日发布了 Decision Index v1.0。它对四项测试等权平均：AA-Omniscience-Decision（知识与幻觉）、HLE-MultiChoice（推理）、When2Call（工具调用）和 WildGuardTest（安全分类）。Jev 1.13 的结果如下：

HLE-MultiChoice21，其他决策模型不超过 15
AA-Omniscience-Decision准确率 35，非幻觉率 35

WildGuardTest94，比 GLiDE 低 1 分

与语言模型相比，Claude Haiku 5.5（Low）得 61 分，每任务 1.4 秒，每百万任务 $184；GPT-6 Luna（Low）得 55 分，1.5 秒，$131。LLM 在知识类题目上领先：在 AA-Omniscience-Decision 上准确率为 52 和 66，决策模型为 28 到 41。Artificial Analysis 还发现决策模型过度自信：在几乎所有概率档位上，实际准确率都低于模型给出的概率，主要出在知识和推理题上，而在工具调用和分类题上校准较好。

Arize 是一家把 Jev 作为内置评审模型提供的评测平台。它在发布约三周后，把 Jev 1.13 与另外 7 个决策模型做了对比。Jev 在 RAGTruth 幻觉检测上的平衡准确率为 85.5%，在 13 套 Phoenix 评估器上为 91.1%，52 个 agent 路由用例答对 49 个。它的校准误差 0.023 是 8 个模型里最低的，不过与 Liquid d1 的区间有重叠。领先的几个模型之间，准确率差异都落在彼此的置信区间内。在措辞测试中，把幻觉问题的说法反过来之后，Jev 的 ROC AUC 仍保持在 0.93，而其他几个模型跌到了 0.5 以下。Arize 的建议是：换用任何新模型之前，把同一问题的两种说法都试一遍。

排名变化很快。10 月 22 日，TechCrunch 把最新的 Jev 放在 Artificial Analysis Decision Index 的第三、AIM System One Index 的第七，排在 Liquid d1-ultra 等较新的模型之后，同时报道 TypeSafe 的模型在某个模型网关上是被调用最多的决策模型。

局限与数据处理

TypeSafe 在一个最近核对于 10 月 2 日的页面里列出了 1.13 的失效模式：

  • Jev 按字面理解问题。把确切条件和边界情况写进 criteria。
  • 它数数不可靠，算术和日期比较也弱。用 Jev 抽取各个部分，计算交给代码。
  • 双重否定和多步推理会降低准确率。
  • 状态里混入无关细节越多，准确率越低，所以发送前先过滤。
  • 状态里的文本可能带偏答案。TypeSafe 说明，Jev 默认不会把状态当作恶意输入。
  • Choice 选项的顺序可能让答案偏向排在前面的选项，可以调换顺序做核对。
  • 它没有被训练去生成文字。

速率限制按组织设置，超限的请求返回 429。TypeSafe 表示 Jev 不会用客户的请求或响应训练，企业客户可以约定不保留请求数据（ZDR）。所有账户使用同一份权重：Jev 不会用客户数据微调，所以领域知识要放进状态和 criteria。

常见问题

Jev 是什么？

TypeSafe AI 的决策模型。你发送文本或 JSON 加上类型化的问题，它返回选项、分数或是/否概率以及置信度，而不是生成的文字。它于 2026年9月15日 以早期访问形式发布。

Jev 是 LLM 吗？

不是。TypeSafe 称它是基于 Transformer 的模型，像 LLM 一样读取自然语言，但只输出类型化答案和概率。它不写文章或代码，不做对话，也不调用工具。

Jev 多少钱？

每百万输入 token $0.042，即每十亿 $42，输出 token 免费。图像按输入 token 以同一价格计费。价格读取于 2026 年 10 月 23 日，模型页上是当前价格。

Jev 1.13 和 Jev 1.14 有什么区别？

Jev 1.14 增加了在图像中定位目标的 Box 问题类型，TypeSafe 预期它的多语言准确率更高。两个版本都在主动开启请求头后接受图像和 262K 长上下文模式，价格相同。

什么是决策模型？

一种从你定义的选项里挑选并给出每个选项概率的模型，不生成文字。TypeSafe 称之为 System One 模型。其他厂商现在也推出了自己的版本，本站 catalog 里 kind 为 decision 的条目有 31 个。

我能自己部署 Jev 吗？

不能。权重和架构均未公布，Jev 只能通过托管 API 使用。其他决策模型，例如 Cloudflare 的 Clef，提供开放权重。

Jev 会产生幻觉吗？

它的答案被限制在你提供的选项里，因此不会返回格式错误的值，也不会给出你没列出的选项。它仍然可能选错，而且 Artificial Analysis 发现决策模型在知识和推理题上过度自信。
